# EF.SOD data group reconciliation

This analysis is completely offline. It parses the signature-verified EF.SOD content already
stored in the session archive and computes the hash of the exact stored DG artifacts. It does not contact
PC/SC or use any credentials.

The SHA-256 of the signed content is
`bbbb3c7af8e6565951dadbcff579fef998053ccf396531da80e473332ff08fa9`.
It signs SHA-256 values for DG1, DG2, DG3, DG7, DG11, DG12, DG13, and DG14.

classified as `signed_not_acquired`; its post-PACE SELECT returned `6982`, so its signed hash
must not be described as acquired or verified against card bytes.

`tools/session/reconcile_sod.py`. This establishes integrity relative to the signed EF.SOD; the separate
CSCA chain limitation is documented in `lab/CSCA_TRUST_DISCOVERY.md`.
